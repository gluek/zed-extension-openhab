# Test Scaffolding for openHAB-Zed Language Server

This directory contains test utilities for validating tree-sitter queries and
generating parse tree snapshots for the openHAB language server extension.

## The Harness

The `tests/harness` directory is a Rust crate that:
- Parses source files using the pinned tree-sitter-java grammar
- Dumps full parse trees for inspection
- Maps query captures onto source lines for validation

The harness binary is built with:
```sh
cd tests/harness && cargo build --offline
```
The helper scripts build it for you if it is missing.

### Why a Custom Cargo Home?

The grammar file lives in `grammars/java/`, which is gitignored. This directory
is downloaded by Zed on first load; the harness resolves it relative to
`CARGO_MANIFEST_DIR` and fails with a hint if it is absent.

Environment variable override:
```sh
JAVA_GRAMMAR=/path/to/grammar  # Optional, if grammar location differs
```

## Commands

### 1. Compile Queries

```sh
harness --compile <query.scm>
```

Validates that a query file compiles without errors. Outputs `ok: <path>` on
success, exits with code 1 on failure. Used by `validate-queries.sh`.

### 2. Dump Parse Trees

```sh
harness <file>... [--tree]
```

Prints the full parse tree of the given file(s). The `--tree` flag is explicit
but equivalent to default behavior.

### 3. Generate Captures Report

```sh
harness --captures <query.scm> <file>...
```

Maps query captures onto source lines. Outputs captures aligned to source lines,
plus a per-file summary (`errors/captures`) and a final count (`N captures over M files`).

Reports are written to `tests/reports/<query>-<fixture>.txt` by
`./tests/report-captures.sh` (it clears the directory first, since stale
reports are worse than none).

### 4. Validate All Queries

```sh
./tests/validate-queries.sh
```

Compiles all `.scm` files in `languages/openhab/`. Prints `PASS <path>` or
`FAIL <path>` per file, then a summary. Exits 0 only if all pass.

### 5. Update Snapshots

```sh
./tests/update-snapshots.sh
```

Generates parse tree snapshots for all fixtures in `tests/fixtures/`. Writes
`tests/trees/<basename>.txt` from `tests/fixtures/<basename>`.

### 6. Check Snapshots

```sh
./tests/check-snapshots.sh
```

Regenerates trees for all fixtures and diffs against snapshots. Prints:
- `OK <basename>` - matches snapshot
- `CHANGED <basename>` - differs from snapshot
- `MISSING <basename>` - no snapshot file exists

Exits non-zero if any file differs or is missing.

## Understanding the Parse Tree

### What Snapshots Pin

The `tests/trees/` directory pins **parse tree only**. This is important:

- Editing `.scm` queries does NOT change the snapshots
- A diff means either:
  - The pinned grammar revision changed (e.g., you pulled an updated grammar)
  - A fixture file changed
  - Review if a query has new impacts on parse structure

### Fixture Parsing Quality

Not all fixtures parse cleanly. This is expected behavior:

| File Type | Parsing Quality | Notes |
|-----------|-----------------|-------|
| `.rules` / `.script` | Best | Well-structured |
| `.items` / `.sitemap` | Partial | Mixed structured + raw text |
| `.things` / `.persist` | Poor | Mostly `ERROR` nodes |

The poor parses in `.things` and `.persist` are expected and represent
exactly what **Phase B** (a purpose-built openHAB grammar) will fix. The
current tree-sitter-java grammar is generic and doesn't understand openHAB's
specific syntax.

## Workflow

### Daily Development

1. **Edit a query file** in `languages/openhab/*.scm`
2. **Validate compilation**: `./tests/validate-queries.sh`
3. **Test on a fixture**: `harness --captures highlights.scm tests/fixtures/sample.items`
4. **Check snapshots**: `./tests/check-snapshots.sh`
5. **Iterate** until all tests pass

### Updating Snapshots

When you intentionally change a fixture (or accept grammar updates):

```sh
./tests/update-snapshots.sh
./tests/check-snapshots.sh  # Should now show all OK
```

### Debugging

```sh
# See the full parse tree
harness tests/fixtures/sample.items

# See captures for a specific query
harness --captures highlights.scm tests/fixtures/sample.items

# Quick compile check
harness --compile languages/openhab/highlights.scm
```

## Generated Reports

`tests/reports/` contains capture reports generated by `harness --captures`.

**Not authoritative**: These are artifacts of running the harness, not manual
documentation. Regenerate them as needed.

## File Organization

```
tests/
├── harness/               # Rust harness crate (do not edit)
│   ├── src/
│   └── target/debug/harness
├── fixtures/              # Source files for testing (do not edit)
│   ├── sample.*
│   ├── r*.rules
│   └── *-edge.*
├── trees/                 # Generated parse tree snapshots
│   └── <basename>.txt
├── reports/               # Generated capture reports (gitignored)
│   └── <query>-<fixture>.txt
├── validate-queries.sh    # Validates all .scm files compile
├── update-snapshots.sh    # Generates fresh tree snapshots
├── check-snapshots.sh     # Compares trees against snapshots
└── README.md              # This file
```

## Rules

- **Do NOT edit**: `languages/**`, `tests/fixtures/**`, `extension.toml`,
  `Cargo.toml`, `src/**`, `plan.md`, `.gitignore`
- POSIX sh only: no bashisms, no arrays, no `local` outside functions
- Deterministic output: all lists are sorted
- Bound command runtime: cargo build is cached, other commands are fast

## Exit Codes

| Script | Exit 0 | Exit 1 |
|--------|--------|--------|
| `validate-queries.sh` | All queries compile | One or more fail |
| `check-snapshots.sh` | All snapshots match | Any CHANGED or MISSING |
| `update-snapshots.sh` | Always | Error writing files |
